3. THE SHEET'S PASSWORD, SHEET_TOKEN. Make up a long random string, 30
   characters or more, letters and numbers, from a password manager or by
   hand. Keep it somewhere safe. Then, one straight after the other:

     a. Cloudflare, minibus-api, Settings, Variables and Secrets, Add:
        type Secret, name SHEET_TOKEN, value the string. Deploy.
     b. Apps Script, Project Settings, Script Properties, Add:
        SHEET_TOKEN, the same string. Save.

   In the minute or two between a and b the sheet's messages are refused.
   Nothing is lost: everything phones do waits on the live server and is
   collected once b is done.

   Optional, in the same place as b:
       SENDER_NAME    Dominion Transport
       WEB_APP_URL    only if the report below asks for it

4. Minibus, Rota and setup, Send everything to the live server now.

5. PAGES. Merge the pull request. GitHub publishes the pages from main.

6. EACH COORDINATOR, ON THEIR OWN PHONE. Open the driver app, signed in as
   themselves, and turn alerts on (the bell at the top of the hub, or the
   offer under it). A phone that already has alerts on for its owner needs
   nothing: it is already on the list.


THE SHEET NOT ANSWERING THE LIVE SERVER
---------------------------------------

"Is everything working?" has said the sheet did not answer. After step 4,
run Minibus, Have a look, Is the live server working? It names the web app the live
server knocks on, by the last six characters of its id.

- If it says the live server knocks on a DIFFERENT web app from this
  script's: step 4 again. If it still differs, Deploy, Manage deployments,
  copy the Web app URL of the deployment in use, put it in the Script
  Property WEB_APP_URL, and step 4 again.

- If it says they are the SAME, and the sheet still does not answer: in
  Deploy, Manage deployments, that deployment must say Execute as: Me and
  Who has access: Anyone. And in Apps Script, Executions, look for doPost:
  none at all means the knocks are not arriving; Failed means they arrive
  and something went wrong, and the entry says what.

Nothing is lost while this is wrong: the sheet still collects every five
minutes by itself. The knock only makes it seconds instead.

WHAT CHANGED
------------

1. COORDINATOR ALERTS ON EVERY COORDINATOR'S PHONE.
   Beside each email the coordinator is sent, the same alert goes to the
   phones: a bus stopped, a defect, an advisory or something to arrange on a
   check, a bus authorised to run, a rota request, a bus that went out
   unchecked, a route overbooked. It goes even with no COORDINATOR_EMAIL set.
   Short on purpose: what happened, and to which bus or Sunday. A phone joins
   the list by typing a name, with no PIN, so the detail stays in the email
   and in the coordinator's app, which the alert opens. A stopped bus goes at
   any hour; everything else waits out 21:00 to 08:00. The person an alert is
   about is not woken by it. Each goes once.

2. A PRIVATE PASSWORD BETWEEN THE SHEET AND THE LIVE SERVER. The token in
   config.js is public, because every phone needs it, and it was all that
   guarded the messages only the sheet and the live server should send each
   other: a sync that replaces the rota, drivers and stops, the drain, a
   decision, a report, a coordinator alert. SHEET_TOKEN, set on both sides,
   now guards those. What phones send is unchanged. Your code and the
   spreadsheet were never editable from outside; this closes the way to feed
   the live server false data.

2a. EMAILS FROM A NAME. SENDER_NAME sets the name every email shows as sent
   by. Replies go to COORDINATOR_EMAIL. The address is still the Google
   account the script runs as.

3. WHERE THE LIVE SERVER KNOCKS. Shown in both reports, settable with
   WEB_APP_URL. See above.

4. DVSA ON THE CHECK. Items on DVSA's daily walkaround check are tagged, and
   the two it had that this list did not are added.

5. THE COORDINATOR'S APP, LIKE THE OTHER TWO. Its version line reads "app";
   it has the Add to your phone guide; Vehicle check is a link beside Driver
   app rather than a menu item.

6. THE TEST MENU ITEM TESTS BOTH. "Test email, to you only" is now "Test
   email and coordinators' phones".
