WHAT CHANGED
------------

1. NO SALT IN A PUBLIC FILE.
   Code.gs and worker.js each carried a fallback PIN salt, and both are in
   a public repository. A system that never had PIN_SALT set was salting
   with a value anybody could read. The fallback is gone from both.

2. A MISSING SALT REFUSES, NEVER OPENS.
   With no PIN_SALT on the sheet, a driver who has a PIN is sent to the
   live server with a fingerprint nothing can match. A blank would have
   meant "no PIN wanted" and let anybody through. With none on the live
   server, no PIN matches there either. "Is everything working?" names the
   side that is missing it.

3. THE COORDINATOR'S NUMBER IS OUT OF THE COMMENTS.
   The code's examples use 07700 900123, a number set aside for drama and
   never given to anybody.

The phone salt is unchanged on purpose. It fingerprints passengers' numbers,
but anybody holding a number can already look up that booking with the
number itself, so a secret salt adds almost nothing, and changing it would
cut every current booking off from the phone that made it.
