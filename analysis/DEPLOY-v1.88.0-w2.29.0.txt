BEFORE YOU START
----------------

Tell the drivers. From this release, on a Sunday morning after bookings
close, a passenger booked on a driver's route can open WhatsApp to that
driver from the passenger page. Only a booked passenger, only for his own
route, only on the morning, and not once the run has ended. A driver who
would rather not: leave his Phone cell on the Drivers tab empty, and there is
no button for his route.

WHAT CHANGED
------------

1. ADD TO YOUR PHONE, FIRST. The install offer and the alerts question rose
   on timers of their own, 600 ms and half a second, and whenever the
   subscription lookup had answered before the stops landed the alerts
   question won. The install sheet then found it up and stood down, and the
   offer never came. The alerts question now waits while the install offer is
   still to come on that visit, and rises as the install sheet closes.
   (sunday/index.html. Browser checks P7, P7b; sabotages S19, S19b.)

2. MESSAGE THE DRIVER. The sheet sends every active driver's WhatsApp number
   on the sync, beside the coordinator's, over the same guarded call. The
   live server names the driver on a route, cover first, only to a phone with
   a seat on that route that Sunday, once bookings have closed and while the
   route is running; everybody else gets nothing. A number too short to be
   real, or none at all, gives no button. (Code.gs driverWhatsApp and
   waNumber; worker.js driverForPassenger; tests/suites/34-message-driver.mjs
   and browser check P8.)

3. THE CHECK THAT WOULD HAVE CAUGHT IT. Is everything working? asks the
   live server whose numbers it holds (names only; the numbers never come
   back) and holds that against the coming Sunday's two drivers, cover
   first, as the passenger page does:

       the tab but not on the live server Needs attention: Send everything
